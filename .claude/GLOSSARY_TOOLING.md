# Глоссарий: инструменты разработки с ИИ (не в git)

Термины про Claude Code и процесс работы с ним. Вынесены из docs/GLOSSARY.md, чтобы docs/ и README
не упоминали ИИ-инструменты (решение пользователя, 2026-10-23); сама папка `.claude/` пока остаётся
в git. Термины о предмете (Flutter, CRDT, Git) — в docs/GLOSSARY.md.

## Конфигурация

- **CLAUDE.md** — файл-инструкция, который Claude читает в начале каждой сессии: роль, стек, команды, правила. Короткий (рекомендация документации — до 200 строк), потому что длинные инструкции модель начинает игнорировать. `@путь` внутри него импортирует файл целиком (у нас — docs/TODOIST_PARITY.md).
- **Правила (`.claude/rules/*.md`)** — те же инструкции, но разбитые по темам. Файл с полем `paths` подгружается только когда Claude открывает подходящие файлы (например, правила про Android — только при работе в `android/`). Экономит контекст. Единственное поле frontmatter, которое читается, — `paths`.
- **Агент / субагент (`.claude/agents/*.md`)** — отдельный «сотрудник» со своим системным промптом, набором инструментов (`tools`), моделью (`model`) и режимом прав (`permissionMode`), которому главный Claude делегирует задачу. Работает в своём контексте и возвращает только итог. У нас 7: architect, sync-engineer, flutter-ui, platform-integrator, qa-tester, parity-reviewer, code-reviewer. Поле `memory: project` даёт агенту папку `.claude/agent-memory/<имя>/` и автоматически добавляет ему Write/Edit — поэтому «только читающим» агентам нужен хук, ограничивающий запись (см. ниже).
- **Скилл (`.claude/skills/<имя>/SKILL.md`)** — многошаговая процедура или справочник, который загружается по вызову `/имя` или когда Claude сам решает, что он нужен (`disable-model-invocation: true` запрещает второе). `/feature`, `/bootstrap`, `/release`, `/sync-check`, `/impact`, `/obligations`, `/freshness`, справочник `todoist-syntax` (указывает на docs/TODOIST_SYNTAX.md). `allowed-tools` — что скилл может запускать без вопроса; `` !`команда` `` в тексте скилла выполняется до показа Claude, и её надо разрешить в `allowed-tools`.
- **Хук (hook)** — скрипт, который Claude Code запускает автоматически при событии: перед вызовом инструмента (PreToolUse), после (PostToolUse), при старте сессии и т.д. В отличие от правил, которые модель может «забыть», хук выполняется всегда. Код выхода 2 = отказ, текст из stderr показывается модели. У нас пять: `guard-generated.ps1` запрещает править сгенерированные файлы, `format-dart.ps1` форматирует Dart после правки, `guard-write-scope.ps1` ограничивает папки записи для агентов qa-tester и parity-reviewer, `readonly-bash.ps1` пускает агента code-reviewer только к командам чтения и проверок из белого списка (оба подключены во frontmatter агентов `hooks:`), `guard-secrets.ps1` не даёт любой команде терминала прочитать ключи подписи и `.env` — запрет `Read(...)` в настройках ловит только часть команд (cat, head), а grep и Get-Content — нет.
- **Exec-форма хука (`command` + `args`)** — хук запускается напрямую как процесс, без оболочки; `${CLAUDE_PROJECT_DIR}` подставляется самим Claude Code. Так работает на Windows без Git Bash и не ломается на пробелах в путях.
- **Permissions (allow / deny)** — список команд и файлов, которые Claude может использовать без вопроса или не может вообще. `deny` сильнее `allow` из любого файла: пользовательский `~/.claude/settings.json` запрещает все git-команды записи (add, commit, push, rm и т.д.), поэтому проектные `allow` для `git add/commit/tag` не действуют — коммитит пользователь сам.
- **attribution** — настройка, управляющая подписью, которую Claude Code добавляет в коммиты (`Co-Authored-By: …`) и описания PR. В проекте выставлена в пустые строки + `sessionUrl: false`: подписи нет. Старое имя настройки — `includeCoAuthoredBy` (устарела с v2.0.62).
- **Plan mode / `permissionMode: plan`** — режим, в котором Claude только читает и планирует, не меняя файлы. Агент architect работает в нём. Если основная сессия в auto/acceptEdits, режим агента наследует её.
- **Фоновый субагент** — по умолчанию субагенты работают в фоне и получают урезанный набор встроенных инструментов (Read, Grep, Glob, Bash, Edit, Write, WebFetch, WebSearch и несколько других); `AskUserQuestion` им недоступен — вопросы пользователю агент возвращает в отчёте.
- **Плагин** — пакет из скиллов, агентов, хуков и MCP-серверов, устанавливаемый одной командой из маркетплейса (`/plugin` в терминале или настройки claude.ai). Описания его скиллов попадают в контекст каждой сессии, поэтому подключать стоит только нужное.
- **MCP-сервер** — внешняя программа, дающая модели инструменты (например, Dart MCP server: анализ, тесты, hot reload, pub). Подключается через плагин или `.mcp.json`.

## Процесс (перенято из соседнего проекта AgroShtab, 25.10.2026)

- **`/impact`** — скилл «проверка влияния»: до изменения принятого решения находит все места в документах, правилах и коде и проходит чек-лист последствий (данные, формат, конфликты, офлайн, паритет, тесты). Нужен, чтобы правка решения не оставила устаревших копий.
- **`/obligations`** — скилл, который ведёт реестр отложенного docs/OBLIGATIONS.md: в начале шага поднимает его строки, после ревью записывает новое, закрывает выполненное только с доказательством.
- **`/freshness`** — скилл проверки актуальности: версии Flutter, пакетов, плагинов анализатора, Actions и рекомендаций платформ по официальным сайтам. Только читает; обновление — отдельной задачей.
- **Обязательные ревьюеры** — code-reviewer перед коммитом в слой данных, parity-reviewer перед отметкой `[x]`, в конце этапа ещё architect. Агент в свежем контексте не знает рассуждений автора и поэтому видит то, что автор пропустил.
- **Хук «только чтение» (`readonly-bash.ps1`)** — делит команду на части по `;`, `&&`, `|` вне кавычек и пропускает только команды из белого списка; перенаправление в файл и подстановка команд блокируются. Сомнение — блок.
- **HOW_TO_WORK.md** — памятка пользователю: что делает он сам на каждом шаге (ветка, ответы «1А, 2Б», Git, `/clear` перед новой задачей).
