# Как работать с Claude Code в этом проекте

Памятка: что делаете вы. Что делает агент на каждом шаге — `/feature` и CLAUDE.md («Задача»,
«Вопросы пользователю и отчёт»).

## Этап
1. Попросите план этапа (номер из docs/ROADMAP.md). Агент пишет план в docs/plans/, поднимает строки
   реестра `/obligations этап <N>` и выдаёт блок «Решения».
2. Отвечаете строкой «1А, 2Б» и утверждаете или правите план. Пока план не утверждён — кода нет.
3. В конце этапа — ревью агентами (code-reviewer, parity-reviewer, architect), `/sync-check`,
   `/obligations конец этапа <N>` и ваша приёмка: «Готово, когда» из ROADMAP.

## Шаг или фича
1. Готовите ветку: прошлый PR слит; `git switch main`, `git pull --ff-only`, `git switch -c <ветка>`.
   Команды — в конце прошлого отчёта.
2. Новая сессия или `/clear`, затем задача (`/feature <пункт TODOIST_PARITY>` или «шаг M2.2 по плану»).
   Историю прошлых сессий перечитывать не нужно: всё нужное — в плане этапа и docs/OBLIGATIONS.md.
3. Агент выдал блок «Решения» — отвечаете «1А, 2Б»; без ответа он код не пишет.
4. Читаете отчёт: сначала «Решения», затем вывод проверок, а не «всё работает».
5. Git делаете вы — по последнему разделу отчёта (его нет, пока есть вопросы). PR на GitHub; CI
   красный — сообщаете агенту в той же сессии; зелёный — сливаете («Create a merge commit»).

## Когда что вызывать
- Хотите изменить принятое решение или требование — `/impact <что меняется>`: все места и последствия
  до правки.
- Что отложено и к какому сроку — `/obligations`; перед релизом — `/obligations релиз`.
- Раз в квартал, перед релизом и когда CI сломался без изменений в коде — `/freshness`.
- После правок слоя данных — `/sync-check`.

## Правила
- Ошибка повторяется — значит, правило сформулировано плохо: правится документ, а не только код.
- Не запускайте несколько агентов параллельно на одни и те же файлы.
- Решения о стеке, версиях, формате данных и необратимых действиях принимаете вы (CLAUDE.md,
  «Decision Gate»).
- Приложение запускается в одном экземпляре на профиль. Пока открыт ваш planner (основной профиль),
  `flutter run -d windows` и `flutter test integration_test -d windows` без профиля не стартуют: второй
  запуск покажет ваше окно и выйдет. Закройте приложение или запускайте разработку с профилем:
  `flutter run -d windows --dart-entrypoint-args=--profile=dev`.
