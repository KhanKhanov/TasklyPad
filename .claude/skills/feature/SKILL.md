Реализуй фичу: **$ARGUMENTS**

1. **Старт.** `git status`: работа идёт в ветке задачи от свежего main. Нет — остановись и дай
   пользователю команды (перейти на main, подтянуть слитое, создать ветку). `/obligations шаг <...>` —
   строки реестра, которые фича должна закрыть.
2. **Пункт ТЗ.** Найди фичу в docs/TODOIST_PARITY.md. Нет — добавь пункт в нужный раздел
   со статусом `[~]`. Если фича большая (несколько пунктов) — предложи разбивку и возьми первый.
3. **Поведение Todoist.** Если синтаксис/семантика неочевидны — агент parity-reviewer
   («опиши поведение Todoist для <фича>») до написания кода. Запиши факты в план.
4. **План.** Если затрагиваются 3+ файла или схема данных — агент architect. Сохрани план в
   docs/plans/<slug>.md: шаги, решения с альтернативами, ссылки на разделы документов (не пересказ),
   номера `О-N`. Меняешь уже принятое решение — сначала `/impact`. Вопросы — по группам из CLAUDE.md
   («нужно сейчас» — блоком «Решения»); пока ответа нет — код не пиши.
5. **Данные.** Новые поля/таблицы — агент sync-engineer (миграция, ops, тест слияния).
6. **Логика и парсеры.** Тесты → код в domain/nlp/features/logic; примеры синтаксиса — в test/fixtures.
7. **UI.** Агент flutter-ui; платформенные части — platform-integrator.
8. **Проверка.** `dart run build_runner build -d` → `flutter analyze` → `dart format .` →
   `flutter test`; слой данных — `/sync-check`. Для UI — `flutter run -d windows`, скриншот.
   Красное — исправить, не отчитываться.
9. **Ревью (обязательно).** code-reviewer на diff, если затронуты lib/data, lib/sync, lib/domain,
   packages/ или миграции; parity-reviewer на фичу. Исправь найденное и повтори проверки.
10. **Сверка.** `/obligations запись`; отметь пункт `[x]` в docs/TODOIST_PARITY.md только после
    parity-reviewer; новые термины — в docs/GLOSSARY.md; итог — в план («Итог»).
11. **Отчёт** — в порядке из CLAUDE.md («Вопросы пользователю и отчёт»). В разделе Git: файлы,
    сообщение `feat(<область>): <что>` (Conventional Commits, без упоминаний ИИ-инструментов), команды
    для PowerShell 5.1, описание PR; после слияния — перейти на main и создать ветку следующей задачи.
