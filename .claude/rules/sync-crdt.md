# Синхронизация: неизменные запреты

Дом — docs/SYNC_DESIGN.md. Перед правкой слоя прочитай «Инварианты реализации» и раздел по теме
(Op, HLC, Merge, «Конфликты», «Проекции», «Специальные случаи», «Транспорт A», «Узел и запуск»).
Здесь — только то, что нельзя нарушать никогда; формулировки, детали и причины — там.

- Данные пользователя пишутся только через `Mutator` (ops и проекция в одной транзакции); прямые
  `update`/`delete` таблиц сущностей запрещены.
- Удаление — tombstone; физически строки уходят только компакцией (M12).
- Время и id — только `AppClock` и `IdGenerator`; `DateTime.now()` и `Random` в domain, data, sync и
  features/*/logic запрещены.
- Логика слияния и конфликтов — только в `packages/oplog_sync`; в lib/sync — адаптеры.
- Формат ops или файлов папки меняется только с bump `v`, миграцией и тестом чтения старого формата.
- Миграция drift — шаги и `user_version` в одной транзакции, после автобэкапа.
- Действие пишет только изменённые поля и только саму сущность; производное (каскад, проект подзадачи,
  деревья) вычисляется при чтении (`Workspace`).
- На базу — один движок (`SyncServices`).
- Каждое изменение слоя — тест с двумя узлами по списку SYNC_DESIGN «Инварианты реализации».
