# Инварианты синхронизации (op-log CRDT, без сервера)

- Источник истины — журнал `ops`. Таблицы сущностей — проекции; `rebuildFromOps()` должен
  восстанавливать их с нуля и покрыт тестом.
- Op = {op_id UUIDv7, node_id, hlc, base?, entity_type, entity_id, field, value_json}.
  `base` — hlc значения поля, которое автор видел перед правкой (null при создании).
  Единственный тип — LWW-регистр на поле. Удаление = поле `deleted=true` (tombstone).
  Физическое удаление только компакцией (tombstone старше 90 дней и подтверждён всеми узлами).
- HLC: wall ms + счётчик + node_id, строка сортируется лексикографически. При приёме
  `local = max(local, remote) + 1`. Op из будущего более чем на 1 час — отклонить с ошибкой в лог.
- Merge: применить, если `op.hlc > field.hlc`; при равенстве побеждает больший node_id.
  Идемпотентность: повторный op (тот же op_id) — no-op. Порядок прихода ops не важен.
- Конфликт (IMPORTANT, решение пользователя): чужая op на поле, у которого текущее значение
  записано другим узлом и `op.base != field.hlc`, — параллельная правка. LWW применяется
  сразу (копии сходятся, проигравшее значение остаётся в журнале), и создаётся сущность
  `conflict` с детерминированным id = sha256(entity_id, field, min(hlc), max(hlc)) и полями
  {entity_type, entity_id, field, ops: [op_id, op_id], resolved: false}. Одинаковые значения —
  не конфликт. Правка vs удаление — тоже конфликт. Пользователь получает уведомление и экран
  «Конфликты»; его выбор = новая op на поле с `base` = текущий hlc + op `resolved=true`.
  До выбора действует результат LWW. Последовательные правки (автор видел чужую) — не конфликт.
- Связи many-to-many (task_labels) — строки с tombstone. Порядок — fractional index;
  конфликт одинаковых ключей разрешать генерацией нового ключа между соседями.
- Завершение повторяющейся задачи = ops (событие completion + новый due). Локально
  «пересчитывать» без ops нельзя.
- Folder-транспорт: каждый узел пишет только в свою папку `sync/nodes/<node_id>/`,
  append-only чанки `<seq>.ndjson`, запись через temp + rename, чужие файлы read-only.
  Курсор чтения по каждому узлу — в `sync_cursors`. Снапшоты `snapshot-<hlc>.ndjson`
  для новых устройств. Формат версионируется полем `v` в заголовке файла.
- LAN-транспорт: те же ops по WebSocket, любой узел может слушать; пары связаны ключом
  сопряжения (QR/PIN), сообщения подписаны HMAC.
- Ядро живёт в `packages/oplog_sync` и не знает о Flutter, drift и файловой системе напрямую;
  в lib/sync — только адаптеры. Логику слияния в адаптеры не выносить.
- Изменение формата ops/файлов → bump версии + миграция + тест чтения старого формата.
- Каждое изменение слоя → тест с двумя in-memory узлами (в пакете — `dart test`, в приложении —
  test/sync): параллельная правка разных полей, правка одного поля (конфликт создан на обоих
  узлах с одним id), последовательная правка (конфликта нет), правка vs удаление, разрешение
  конфликта на одном узле закрывает его на другом, оба завершили повторяющуюся,
  переупорядочивание, долгий офлайн одного узла, повторная доставка.
- Миграции drift идемпотентны; перед миграцией — автобэкап БД.
