Массовые действия идут через `TaskCommands.completeEach / uncompleteEach / duplicateEach` с одним
снимком; `_Steps` перечитывает его, только если прошлый шаг изменил то, что читает следующий:
`tree:<корень>` (дерево задачи), `section:<id>` (возврат раздела из архива), `labels` (метки,
созданные заново). Остальное шаги пишут в `_Steps` поверх снимка: возвращённые задачи и их ключи
(соседи для `_returnKey`), копии и их ключи по группе соседей, ключи дня копий, прирост активных в
проекте (лимит 300).
**Why:** замер 300 выделенных при 3000 выполненных: ~5 с на действие (снимок 40 мс × 300); после —
0,5–0,8 с (под нагрузкой параллельных прогонов 1,2–1,8 с).
**How to apply:** новый шаг массового действия, который читает что-то общее для разных деревьев
(метки, раздел, соседей, счётчик проекта), — добавить ключ зависимости или учёт в `_Steps`, и
закрепить тестом эквивалентности test/features/tasks/bulk_steps_equivalence_test.dart с мутацией.
Связано: [[test-pitfalls-windows]].
