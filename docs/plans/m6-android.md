## Ключевые решения

### `SafSyncFs` (О-30, О-34)
- Реализует `SyncFs` (packages/oplog_sync/lib/src/fs.dart) поверх канала на Kotlin. URI дерева хранится в
  `local_meta` — память устройства, как путь папки на Windows (SYNC_DESIGN «Специальные случаи»). Реализацию
  выбирает `SyncRunner(openFs:)` в lib/app/sync_providers.dart по платформе.
- Путь → id документа обходом дерева; кэш id детей — на один проход, при промахе сбрасывается (id облачных
  хранилищ непрозрачны).
- `exists('')` — `false`, если URI нет среди постоянных разрешений или запрос корня даёт `SecurityException`
  или `FileNotFoundException`.
- `writeString` — временный документ, запись, переименование; существующий целевой удаляется перед
  переименованием (не атомарно; так пишется только `info.json`, сбой — замечание отчёта).
- `writeStringIfAbsent` — проверка, временный документ, переименование; если система вернула другое имя
  (`000003 (1).ndjson`), файл удаляется, ответ `false`. Документация DocumentsProvider разрешает хранилищу
  менять имя при создании и переименовании.

### Фоновая синхронизация и один движок (О-42, О-51)
- Проверено по исходнику: workmanager на каждый запуск поднимает отдельный `FlutterEngine` и уничтожает его
  после; `shareAcrossIsolates` drift работает только внутри одного engine. Значит, база интерфейса и фоновой
  задачи общей быть не может — движок передаётся по очереди.
- Интерфейс регистрирует порт `planner.ui` в `IsolateNameServer`, фоновая задача — `planner.bg`. Фоновая
  задача, получив ответ на пинг от `planner.ui`, базу не открывает и просит интерфейс синхронизироваться;
  иначе — `bootstrap()` → проход → снять аренду → закрыть базу. Интерфейс до `startSync` пингует `planner.bg`
  и ждёт конца фонового прохода. Пинг с ответом, а не наличие имени: имя переживает убитый изолят.
- `SyncScheduler` (lib/sync, без Flutter): период, debounce, «вернулись», «ушли в фон», проходы не
  параллельны; `SyncController` — тонкая обёртка. Интерфейс `BackgroundSync` в lib/platform с фейком.

### Решения M6.1 (пользователь, 22.11.2026)
1Б — id метки, созданной заново при возврате задачи в работу, строится от `labelNameKey` (как поиск живой
метки): «Ёлка» и «елка» в снимках дают одну метку и на двух устройствах офлайн; спор о написании — карточка,
как у регистра (SYNC_DESIGN, правило возврата метки). Формула влияет только на новые ops: id записан в op,
пересборка из журнала не меняется; пока одно устройство на старой версии, для имён с «ё» один раз может
получиться пара — обе сборки обновлять вместе. Тест — test/sync/m4_entities_test.dart «…различаются только «ё» и «е»…» (со старой формулой
падает). Отклонено: А — оставить `toLowerCase` и записать исключение (правило 9А на одном и на двух
устройствах разное).

## Риски
- Облачные приложения могут не давать выбрать папку через SAF (для OneDrive и Google Drive официального
  источника нет) — тогда на телефоне только Syncthing или зеркало облака.
- Список и переименование у облачных хранилищ могут отставать от сервера; защита — проверка возвращённого
  имени и неизменяемые чанки.
- Сборку APK может остановить сборка native assets (`cnativeapi` у пакетов окна, трея, хоткея) — не
  проверено, выяснится в M6.1.
- workmanager откладывает работу: 15 мин — минимум; в Doze задачи не идут до окна обслуживания; после 8 дней
  без запуска (Android 13+) приложение попадает в группу Restricted — раз в сутки.
- Потерянный ключ подписи — обновить приложение нельзя, только переустановить (база телефона вернётся из
  папки синхронизации). Смена `applicationId` после установки — другое приложение.
