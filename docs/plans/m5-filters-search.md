## Ключевые решения

### Модель данных фильтра (2А, 3А, 4А)
Сущность `filter`, таблица-проекция `filters`; имена полей — как у фильтра в API Todoist (импорт — M11):

| поле op | тип, умолчание | слияние |
|---|---|---|
| `name` | text `''` | LWW, спор — карточка и пометка |
| `query` | text `''` | LWW, спор — карточка и пометка |
| `description` | text `''` | LWW, спор — карточка без пометки (как описание проекта, решение 1А plans/m4 «План 1Б») |
| `color` | text `'charcoal'` | LWW, спор — карточка и пометка |
| `is_favorite` | bool `false` | LWW, спор — карточка |
| `order_key` | text, fractional index | молча (`silentFields`) |
| `deleted` | bool `false` | tombstone; удаление против правки — карточка удаления |

`view_options.filtered_by` (text, nullable) — фильтр «Отображения» вида (`filtered_by` в API). Чтение — в снимке
`Workspace` (`readsFrom` WorkspaceRepository), чтобы фильтры, поиск и `Ctrl+K` брали один снимок. Модель —
`SavedFilter` (lib/domain/models.dart): имя `Filter` заняли бы узлы запроса. Команды — lib/features/filters/logic:
добавить, изменить, избранное, порядок, дублировать (с настройками вида, как дубликат проекта), удалить — с
подтверждением, без тоста, как метка. Лимиты О-80 — в `Limits`: имя 60, запрос 1024 кодовые точки, 150 фильтров.
Запрос хранит имена, а не id: переименование проекта ломает фильтр — так в Todoist, help велит править запрос.

### Язык фильтров
- Узлы запроса (sealed-классы) — lib/domain/filter_query.dart; разбор — lib/nlp/filter_parser.dart (лексер —
  отдельный файл): рекурсивный спуск, `!` сильнее `&`, `&` сильнее `|`, `,` — только на верхнем уровне. Даты
  в аргументах — `DateGrammar` на подстроке в режиме фильтра: `-N days`, `first day`, `N days after <дата>`
  включаются только в этом режиме, чтобы быстрое добавление не изменилось (проверка — quick_add.json, dates.json,
  recurrence.json без правки ожиданий).
- Ошибка — `FilterSyntaxError {start, end, kind}`; текст — l10n в UI, в lib/nlp строк интерфейса нет.
- Вычисление — lib/domain/filter_engine.dart: `evaluate(Workspace, FilterQuery, today, now)` → списки по `,`.
  Проект — вычисленный (`rootProjectOf`, О-6), `##` — `projectSubtree`, раздел — `rootSectionOf`. Только
  активные задачи (help). Свёртка «регистр, ё → е» — одна функция в lib/domain для фильтра, поиска и сортировки
  (сейчас написана дважды: lib/nlp/scanner.dart и lib/domain/view_order.dart).
- Порядок по умолчанию (help «Default sorting order», О-85): фильтр без дат — приоритет → дата и время →
  дедлайн → порядок проекта → порядок задачи; с датами — дата и время (или дедлайн, если даты нет) → приоритет →
  дедлайн → ручной → создание. «С датами» — в запросе есть условие на дату (толкование — допущение).
- Табличные тесты — test/fixtures/filters.json (формат — test/fixtures/README.md): `expect.ast` или
  `expect.error`, и `expect.tasks` по снимку test/fixtures/filter_workspace.json.

### Поиск и `Ctrl+K` (5А, 6А)
- Поиск (help «Introduction to search»): задачи (название, описание), проекты, разделы, метки, фильтры;
  комментарии — M8. Сверху «Лучшие совпадения», дальше выбор типа. Архивные проекты и их задачи не ищутся.
  `*` — часть слова; операторы фильтра в строке поиска работают, `%метка` запускает поиск как фильтр. Внизу —
  «Искать в выполненных»: только название и описание, только целые слова, без меток. «Сохранить как фильтр».
  Недавние: до пяти слов, убрать все или по одному (5А — синхронизируемые настройки). Под строкой поиска —
  недавно открытые задачи, проекты, виды (вопрос к M5.4).
- `Ctrl+K` — «Quick Find» help: переходы к видам, проектам, меткам, фильтрам и действия; список переходов —
  тот же, что у клавиш shell_keys.dart, а не копия. Состав в help не описан (вопрос к M5.4).
- Клавиши: `/`, `f` — поиск (help); `Ctrl+F` и `Ctrl+Shift+F` — в help строки «mobile keyboard», делаем и на
  Windows, как `Ctrl+1/2/3` в M4.6.

## Сверка с Todoist (13.11.2026, ссылки — «Источники»)
- Синтаксис — TODOIST_SYNTAX §4. `date` — запланированная дата, `due` — дата или дедлайн; `overdue` — только
  по дате; `%` — метка, `@` уходит к концу 2026; `\` экранирует; `!/*` — вне разделов.
- Фильтр показывает только активные задачи; комментарии недоступны.
- Окно фильтра: имя, цвет, запрос; «Избранное»; описание — у существующего фильтра, под именем над результатами.
- Порядок фильтров — перетаскиванием; в избранном — порядок списка, группы: проекты, метки, фильтры.
- Лимиты (help «Usage limits»): имя 60, запрос 1024, фильтров 150 (тарифное «3» — вне scope §11).
- Вид фильтра: список (доска и календарь — M8); фильтры сортируются по умолчанию, вручную не упорядочиваются.
- Поиск и клавиши — «Поиск и `Ctrl+K`» выше.

### Не найдено в help (допущения, О-69)
`&` сильнее `|`; регистр и «ё»; ключевые слова обоих языков при любом интерфейсе (7А); `срок` = `date`,
`к выполнению` = `due`; `today` и дата без `date:` — только по дате, без дедлайна; `N days` — с сегодняшним днём,
без просроченных; дата без года; несуществующее имя — пустой список; заголовок списка при `,` — текст части;
сообщение и подсветка ошибки; живой предпросмотр в окне; дубликат фильтра; подтверждение удаления; лимит
описания фильтра — 16383, как у проекта; счётчик у фильтра; «С датами» в порядке по умолчанию.

## Тесты (сводно)
- filters.json — каждая строка TODOIST_SYNTAX §4 и примеры help из «Сверки»; ошибки с позицией.
- Вычисление: подзадача, перенесённая с родителем (О-6); задача только с дедлайном (О-85, `due` против `date`);

## Риски
- Режим фильтра в `DateGrammar` может задеть быстрое добавление — fixtures M3 без правки ожиданий.
- Одноимённые проекты или метки, созданные офлайн на двух устройствах, совпадут с `#Имя` оба.
- Поиск в памяти не покрывает комментарии M8 — к M8 расширить снимок или вернуться к индексу.
- `filtered_by` затрагивает «Отображение» всех видов — M5.3 шире экрана фильтра.
- Замена импорта Flutter (M5.1a) в ~145 файлах — только между шагами, иначе конфликты слияния.
